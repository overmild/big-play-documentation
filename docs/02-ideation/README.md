# Ideation

A lightweight place to float and refine ideas before they become formal requirements — cheap to write, cheap to change, cheap to reject.

## When to write a proposal
- A new feature or direction you think Big Play should pursue
- A significant change to something already agreed
- Anything where you want input *before* committing time to it

You don't need one for small fixes, typos, or obvious clarifications — just edit directly (see `CONTRIBUTING.md`).

## Process
1. Copy `template-proposal.md` into this folder, name it `YYYY-MM-DD-short-title.md`.
2. Fill in what you can — it's fine to leave "Open questions" mostly empty at first.
3. Open a PR (see `CONTRIBUTING.md` Path A or B). This starts the discussion.
4. After discussion, a maintainer marks it **Accepted**, **Rejected**, or **Needs rework** (see `GOVERNANCE.md`).
5. If accepted, the relevant parts get turned into one or more files in `docs/01-requirements`, and if it involved a significant structural choice, an ADR in `docs/03-decisions`.
